## 一、项目概述

一个轻量级本地清单（To-Do）桌面应用，使用 Markdown 文件作为存储媒介，完全兼容 Obsidian 查看体验。支持选择文件夹作为工作区、按日期/自定义命名清单、未完成项跨清单迁移、清单项与清单文件双层置顶、多行文本、拖拽排序等核心能力。

### 核心价值

- **文件即数据**：所有清单都是普通 `.md` 文件，可直接用 Obsidian / VSCode / 任意编辑器打开，无锁定。
- **轻量级**：Tauri 应用安装包约 5-10MB，运行内存 20-100MB（相比 Electron 节省 80%+）。
- **零网络依赖**：纯本地运行，数据不离开设备。
- **Obsidian 兼容**：使用标准 `- [ ]` / `- [x]` 语法，双向互通。
- **置顶不侵入 md**：清单项置顶与清单文件置顶状态均独立存 localStorage，md 文件保持纯净。

## 三、技术选型

### 3.1 为什么选 Tauri 2.0

| 维度 | Tauri 2.0 | Electron |
| --- | --- | --- |
| 安装包 | 2-10MB | 80-200MB |
| 空闲内存 | 20-100MB | 200-500MB |
| 后端语言 | Rust（内存安全） | Node.js |
| 渲染内核 | 系统原生 WebView | 自带 Chromium |
| 文件 I/O | 官方 plugin-fs + 自定义命令 | Node fs |

本应用 95% 操作是本地文件 I/O，无重渲染需求，Tauri 的轻量化优势能完全发挥。

### 3.2 为什么前端选 Vue 3

- Composition API + `<script setup>` 表达力强，适合中小型工具应用
- Pinia 状态管理简洁直观
- Vite 开发体验丝滑，HMR 秒级热更新
- 学习曲线平缓

### 3.3 关键决策：文件操作走自定义 Rust 命令

**背景**：Tauri 2.0 的 `plugin-fs` 默认禁止访问任何路径，需要用 scope 显式声明白名单。但用户运行时才选择目录，无法预先写死 scope。

**方案**：在 [src-tauri/src/lib.rs](file:///d:/Jesse/allinone/allinone-app/src-tauri/src/lib.rs) 中实现 5 个自定义命令，直接用 `std::fs` 操作文件，绕开插件 scope 限制：

- `list_md_files` — 列出目录下 md 文件
- `read_text_file` / `write_text_file` — 读写文件
- `path_exists` — 判断存在
- `join_path` — 跨平台路径拼接

前端 [src/lib/fs.ts](file:///d:/Jesse/allinone/allinone-app/src/lib/fs.ts) 通过 `invoke` 调用这些命令。

## 五、核心设计

### 5.1 Markdown 格式（Obsidian 兼容）

文件名：`YYYY-MM-DD.md`（如 `2026-06-25.md`）或自定义名称（如 `项目计划.md`）

内容模板：

```markdown
# 2026-06-25 清单

## 待办

- [ ] 完成技术选型文档
- [ ] 搭建 Tauri 项目骨架
- [x] 调研框架对比 #done

## 备注

- 任何自由文本均可，Obsidian 会正常渲染
```

解析规则（[src/lib/markdown.ts](file:///d:/Jesse/allinone/allinone-app/src/lib/markdown.ts)）：

- 行首匹配 `^(\s*)[-*+]\s+\[( |x|X)\]\s+(.*)$` 即为清单项
- `[ ]` = 未完成，`[x]` = 已完成（小写 x，Obsidian 标准）
- 非清单行原样保留，编辑时不破坏标题/备注结构
- 多行待办：文本中的 `\n` 保留，渲染时 `white-space: pre-wrap` 自然换行
- `buildChecklistContent(title, items)`：title 参数既支持日期也支持自定义名称

### 5.2 双层置顶设计（不侵入 md）

应用支持两个层级的置顶，**均不修改 md 文件**，状态独立存 localStorage：

| 层级 | 存储模块 | 标识方式 | 视觉 |
| --- | --- | --- | --- |
| 清单项置顶 | [src/lib/pin.ts](file:///d:/Jesse/allinone/allinone-app/src/lib/pin.ts) | `文件路径 + :: + 文本内容` | 左侧蓝色条 + 浅蓝背景 + ★ |
| 清单文件置顶 | [src/lib/filePin.ts](file:///d:/Jesse/allinone/allinone-app/src/lib/filePin.ts) | `文件绝对路径` | 侧边栏左侧蓝色条 + 📌图标 |

**为什么用文本/路径而非行号**：避免文件编辑后行号变化导致置顶错位。

**清单项展示规则**（`displayItems` 计算属性）：
1. 未完成 + 置顶 → 最顶
2. 未完成 + 普通 → 中间
3. 已完成 + 置顶 → 次底
4. 已完成 + 普通 → 最底

**清单文件展示规则**（`displayFiles` 计算属性）：
1. 置顶文件 → 顶部（保持原相对顺序）
2. 普通文件 → 其后（保持原相对顺序）

**刷新时机**：`refreshFiles` 时只保留当前文件夹下确实存在的置顶文件，避免遗留无效记录。

### 5.3 自定义命名清单

`createNamedList(rawName)` action（[src/stores/checklist.ts](file:///d:/Jesse/allinone/allinone-app/src/stores/checklist.ts)）：

1. 清洗名称：`trim()` + 替换非法字符 `\/:*?"<>|` 为 `_`
2. 补 `.md` 后缀（若用户未输入）
3. `uniquePath` 处理重名（追加 `-2`/`-3`）
4. 标题用去掉扩展名的名称生成内容
5. 写盘 → 刷新文件列表 → 自动打开

**为什么用原生 `window.prompt`**：轻量，避免引入额外 UI 组件。后续可迭代为自定义弹窗。

### 5.4 多行换行

- 输入框：`<textarea>` 自适应高度，Enter 添加 / Shift+Enter 换行
- 编辑框：同上，Enter 保存 / Shift+Enter 换行
- 展示：`white-space: pre-wrap` + `word-break: break-word`，保留 `\n` 与空格

### 5.5 完成态视觉

不使用删除线（划线后看不清），改为：
- 文字颜色降为 `--text-muted`
- 透明度 0.75
- 复选框填充绿色 + 白色对勾

### 5.6 拖拽排序设计

**核心挑战**：用户看到的是 `displayItems`（按置顶/完成重排后的视图），但拖拽要改变 md 文件中清单项的物理行位置。两者顺序不一致，需要通过 `lineIndex` 桥接。

**数据流**：

1. 拖拽源 dragstart → 记录源项的 `lineIndex`
2. 拖过其他项 → 根据鼠标在项的上/下半部，确定目标项 + `before`/`after` 位置
3. drop → 调用 `store.moveItem(fromItem, toItem, pos)`
4. store 调用 `moveItemLine(parsed, fromLine, toLine, pos)` 搬移文件物理行
5. 重新解析整文件 → `displayItems` 自动按新顺序 + 置顶/完成规则重排
6. 回写磁盘，Obsidian 同步可见新顺序

**实现要点**：

- 整行搬移（[src/lib/markdown.ts](file:///d:/Jesse/allinone/allinone-app/src/lib/markdown.ts) `moveItemLine`）：操作 `parsed.lines` 数组，splice 源行后重新计算目标索引（处理 fromLine < toLine 时索引偏移），再 splice 插入
- 拖拽状态集中管理在 [ChecklistView.vue](file:///d:/Jesse/allinone/allinone-app/src/components/ChecklistView.vue)：`dragSourceLine` / `dragOverLine` / `dragOverPos` 三个 ref
- dragenter/dragleave 计数器：HTML5 DnD 在子元素间冒泡会反复触发，用 `Map<lineIndex, count>` 确保只在真正离开整个项时清空指示线
- 视觉反馈：拖拽中源项半透明、目标项顶/底蓝色 2px 指示线、左侧 `⠿` 拖拽手柄
- 编辑模式下禁用拖拽：`draggable="!editing"`，避免与 textarea 文本选区冲突
- 同一清单内拖拽，不支持跨清单

**⚠️ Tauri 2.0 关键坑点：必须禁用原生拖放转发**

Tauri 2.0 在 Windows（WebView2）和 macOS（WKWebView）上**默认会把 HTML5 拖放事件转发给原生窗口**，导致前端的 `dragover` / `drop` 事件被吞掉。表现为：拖动时源项半透明（dragstart 触发了），但松手无反应（drop 不触发），F12 也无报错。

**解决方案**：在 [tauri.conf.json](file:///d:/Jesse/allinone/allinone-app/src-tauri/tauri.conf.json) 窗口配置里设置 `"dragDropEnabled": false`。

副作用：应用不再支持把外部文件拖入窗口。本应用无需此能力，禁用无影响。

### 5.7 迁移逻辑

`createNextListWithCarryover`（[src/stores/checklist.ts](file:///d:/Jesse/allinone/allinone-app/src/stores/checklist.ts)）：

1. 从当前文件名推断日期；若非日期格式则用今天
2. 计算下一天日期作为新清单名
3. 提取当前清单所有 `- [ ]` 项文本
4. 生成新文件内容（含迁移项作为初始待办）
5. 写入磁盘 → 刷新文件列表 → 自动打开新清单
6. **旧清单保留不变**

### 5.8 状态管理

Pinia store `useChecklistStore` 集中管理：

- 文件夹路径、文件列表、当前打开文件
- 解析后的清单项、原始内容
- 清单项置顶指纹集合（响应式 Set）
- 清单文件置顶路径集合（响应式 Set）
- 错误信息、loading 状态

所有文件写操作都即时回写磁盘，无内存脏数据风险。

## 六、运行与打包

### 6.1 环境要求

- Node.js 18+（实测 24.15.0）
- Rust 1.94.0（项目固定版本，见 `rust-toolchain.toml`）

### 6.2 开发模式

```powershell
cd D:\Jesse\allinone\allinone-app
npm install        # 首次
npm run tauri dev
```

首次启动编译 Rust 依赖约 5-10 分钟，后续增量编译很快。前端 HMR 秒级热更新。

### 6.3 打包

```powershell
cd D:\Jesse\allinone\allinone-app
npm run tauri build
```

产物位置：

```
src-tauri\target\release\
├── allinone-app.exe                              # 绿色版，双击即用
└── bundle\nsis\allinone-app_0.1.0_x64-setup.exe  # NSIS 安装包
```

打包配置（[tauri.conf.json](file:///d:/Jesse/allinone/allinone-app/src-tauri/tauri.conf.json)）：

- `targets: ["nsis"]` — 只生成 NSIS 安装包，跳过 msi 节省时间
- `installMode: "perMachine"` — 安装到 `C:\Program Files\`
- `languages: ["SimpChinese", "English"]` — 中英双语安装界面
- `dragDropEnabled: false` — 禁用原生拖放转发，让前端获得 HTML5 DnD 控制权

### 6.4 ⚠️ 沙箱限制说明

Trae IDE 沙箱内无法编译 Rust（build script 子进程管道受限），**所有 `npm run tauri dev` / `npm run tauri build` 必须在沙箱外的常规 PowerShell 执行**。沙箱内仅可运行 `npm run build`（前端构建）。

## 九、常见问题

**Q：点击新建清单无反应？**
A：已修复。原因是 Tauri 2.0 fs 插件 scope 限制 + 错误被静默吞掉。现改为自定义 Rust 命令绕开 scope，所有错误显示在界面顶部红条 + DevTools Console。

**Q：拖拽完全无法移动？F12 也无报错？**
A：Tauri 2.0 默认把 HTML5 拖放事件转发给原生窗口。已在 [tauri.conf.json](file:///d:/Jesse/allinone/allinone-app/src-tauri/tauri.conf.json) 设置 `"dragDropEnabled": false` 修复。需重启应用（Rust 配置改动，HMR 不生效）。

**Q：Rust 编译报 "link.exe not found"？**
A：缺 MSVC 工具链。装 [Visual Studio Build Tools 2022](https://visualstudio.microsoft.com/zh-hans/visual-cpp-build-tools/)，勾选"使用 C++ 的桌面开发"。

**Q：Rust 编译报 "code: 0 操作成功完成" panic？**
A：Rust 1.95.0 工具链 bug。项目已用 `rust-toolchain.toml` 固定 1.94.0，确认 `rustc --version` 显示 1.94.0。

**Q：杀毒软件报警？**
A：未签名的 exe 可能被误报。可临时关闭杀毒，或后续用代码签名证书签名。

**Q：置顶状态会同步到 Obsidian 吗？**
A：不会。项级和文件级置顶均仅存应用 localStorage，md 文件保持纯净，Obsidian 看到的就是原始清单。

**Q：自定义清单名称输入了非法字符？**
A：自动替换 `\/:*?"<>|` 为 `_`，不会创建失败。如输入 `a/b:c` 会生成 `a_b_c.md`。

**Q：拖拽排序会修改 md 文件吗？**
A：会。拖拽改变清单项在 md 文件中的物理行顺序，回写磁盘后 Obsidian 同步可见新顺序。
