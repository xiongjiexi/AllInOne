# AllInOne 项目说明

> 最后更新：2026-07-14
> 版本：v0.7
> 技术栈：Tauri 2.0 + Vue 3 + TypeScript + Pinia + Vite + CodeMirror 6

## 一、项目概述

AllInOne 是一个**多工具合一**的本地桌面应用，目前在同一个壳下集成五个独立工具：

| 工具 | 定位 | 存储媒介 |
| --- | --- | --- |
| 📋 **清单** | 个人待办 / 日报 | Markdown 文件（Obsidian 兼容） |
| ⚡ **GitFast** | 多仓库 git 快速操作 | YAML 配置文件 |
| 📜 **Script Runner** | 多仓库脚本批处理 | YAML 配置文件 |
| 🔀 **Code Review** | 公司内部代码评审创建 | YAML 配置文件 |
| 📓 **笔记** | Markdown 笔记编辑与阅读 | Markdown 文件（Obsidian 兼容） |

### 核心价值

- **多工具不杂糅**：每个工具独立 `features/<name>/` 目录，代码、状态、配置文件完全分离
- **文件即数据**：清单/笔记用 `.md`、GitFast/Script Runner/Review 用 `.yaml`，均可用任意编辑器修改
- **轻量级**：Tauri 安装包 5-10MB，运行内存 20-100MB（相比 Electron 节省 80%+）
- **零网络依赖**：纯本地运行，数据不离开设备
- **跨平台**：Windows / macOS / Linux 均可运行

### 五工具关系图

```
                ┌─ 📋 清单工具（独立 features/checklist/）
                │   └─ .md 文件存储（Obsidian 兼容）
                │
                ├─ ⚡ GitFast（独立 features/gitfast/）
                │   └─ 终端（单仓库 PTY 交互）
                │
AllInOne ───────┼─ 📜 Script Runner（独立 features/scripts/）
                │   └─ 脚本定时执行 + 日志
                │
                ├─ 🔀 Code Review（独立 features/review/）
                │   └─ 评审创建（参数化脚本执行 + 日志）
                │
                └─ 📓 笔记（独立 features/notes/）
                    └─ .md 文件存储（编辑/阅读双模式）
```

> 五工具代码零交叉，仅共享顶层的 `Toolbar.vue`（工具切换器）和 `stores/tool.ts`（当前激活工具状态）。

## 三、技术选型

### 3.1 为什么选 Tauri 2.0

| 维度 | Tauri 2.0 | Electron |
| --- | --- | --- |
| 安装包 | 2-10MB | 80-200MB |
| 空闲内存 | 20-100MB | 200-500MB |
| 后端语言 | Rust（内存安全） | Node.js |
| 渲染内核 | 系统原生 WebView | 自带 Chromium |
| 文件 I/O | 官方 plugin-fs + 自定义命令 | Node fs |

### 3.2 为什么前端选 Vue 3

- Composition API + `<script setup>` 表达力强
- Pinia 状态管理简洁直观
- Vite 开发体验丝滑，HMR 秒级热更新

### 3.3 关键决策：文件操作走自定义 Rust 命令

**背景**：Tauri 2.0 的 `plugin-fs` 默认禁止访问任何路径，需要 scope 白名单，但用户运行时才选择目录，无法预先写死 scope。

**方案**：在 [src-tauri/src/lib.rs](file:///d:/Jesse/allinone/allinone-app/src-tauri/src/lib.rs) 中实现自定义命令，直接用 `std::fs` 操作文件，绕开插件 scope 限制：

- `list_md_files` / `read_text_file` / `write_text_file` / `path_exists` / `join_path` — 清单工具用
- `open_in_explorer` — 清单/笔记右键打开文件夹
- `gitfast_pty_spawn` / `gitfast_pty_write` / `gitfast_pty_resize` / `gitfast_pty_kill` / `gitfast_branch_list` — GitFast 用
- `scripts_scan_repos` / `scripts_run_in_repo` — Script Runner 用
- `notes_list_md_files` / `notes_rename_file` / `notes_delete_file` / `notes_file_stat` — 笔记工具用（清单的 read/write/exists/join_path/open_in_explorer 复用）

### 3.4 关键决策：笔记编辑器选 CodeMirror 6

| 方案 | 包体积(gzip) | 编辑体验 | 可扩展性 | 结论 |
| --- | --- | --- | --- | --- |
| 原生 `<textarea>` | 0 | 差（无语法着色、无行号、无查找替换） | 低 | 体验不达标 |
| **CodeMirror 6** | ~85KB | 优（md 着色、行号、折叠、查找替换、撤销栈、多光标） | 极高（模块化按需引入） | **采用** |
| Monaco | ~1.5MB | 极优（IDE 级） | 高 | 体积过大 |
| Tiptap/Milkdown | ~200KB | 优（所见即所得） | 中 | 隐藏 md 源码，与"编辑 md 文件"诉求不符 |

**选型理由**：CodeMirror 6 模块化架构（核心 + 语言包 + 主题按需引入），原生支持 Markdown 语法着色，自带 undo/redo、查找替换、标准快捷键，虚拟滚动支持长文档。通过 `Compartment` 实现主题动态切换（无需重建实例）。

**Markdown 渲染**：`marked`（~12KB gzip），轻量快速，开启 GFM（GitHub Flavored Markdown）。

### 3.5 跨平台支持

| 平台 | Shell | 终端 | 打包格式 |
| --- | --- | --- | --- |
| Windows | Git Bash（GitFast）/ cmd.exe（Script Runner 默认） | WebView2 | NSIS 安装包 |
| macOS | 系统 bash | WKWebView | .app / .dmg |
| Linux | 系统 bash | WebKitGTK | AppImage / deb |

1. **features/ 目录隔离**：每个工具的组件、lib、store、types 都在自己的子目录，互不依赖
2. **共享最小化**：五工具仅共享 `Toolbar.vue` 和 `stores/tool.ts`，其余无交叉（笔记工具有独立 fs.ts 和 filePin.ts，不与清单混用）

4. **路径别名**：vite.config.ts 和 tsconfig.json 配置 `@` → `src`，便于跨目录引用（如 NoteEditor 引用全局 theme store）

## 五、核心设计

### 5.1 工具切换机制

[stores/tool.ts](file:///d:/Jesse/allinone/allinone-app/src/stores/tool.ts) 管理 `current: ToolId`（`'checklist' | 'gitfast' | 'scripts' | 'review' | 'notes' | 'textutils'`），持久化到 localStorage。

[App.vue](file:///d:/Jesse/allinone/allinone-app/src/App.vue) 用 `v-show`（非 `v-if`）切换五工具，**保留各工具状态**（清单保留当前文件、GitFast 保留终端会话、Script Runner 保留历史、Review 保留配置和表单、笔记保留当前内容和编辑模式）。

### 5.2 清单：Markdown 格式（Obsidian 兼容）

文件名：`YYYY-MM-DD.md` 或自定义名称（如 `项目计划.md`）

内容模板：

```markdown
# 2026-06-27 清单

## 待办

- [ ] 完成技术选型文档
- [ ] 搭建项目骨架
- [x] 调研框架对比

## 备注

- 任何自由文本均可，Obsidian 会正常渲染
```

解析规则（[features/checklist/lib/markdown.ts](file:///d:/Jesse/allinone/allinone-app/src/features/checklist/lib/markdown.ts)）：

- 行首匹配 `^(\s*)[-*+]\s+\[( |x|X)\]\s+(.*)$` 即为清单项
- 非清单行原样保留，编辑时不破坏标题/备注结构
- `buildChecklistContent(title, items)`：title 既支持日期也支持自定义名称

### 5.3 清单：双层置顶（不侵入 md）

| 层级 | 存储模块 | 标识方式 | 视觉 |
| --- | --- | --- | --- |
| 清单项置顶 | [pin.ts](file:///d:/Jesse/allinone/allinone-app/src/features/checklist/lib/pin.ts) | `文件路径 + :: + 文本内容` | ★ |
| 清单文件置顶 | [filePin.ts](file:///d:/Jesse/allinone/allinone-app/src/features/checklist/lib/filePin.ts) | `文件绝对路径` | 📌 |

**为什么用文本/路径而非行号**：避免文件编辑后行号变化导致置顶错位。

**清单项展示规则**（`displayItems`）：
1. 置顶项 → 顶部
2. 非置顶项 → 按文件原顺序
3. 已完成项 **不再沉底**，保持原位

### 5.4 清单：上下移动按钮（替代拖拽）

**历史**：原 v0.4 用 HTML5 拖拽排序，但 Tauri 2.0 的 `dragDropEnabled: false` + 混合置顶场景下行号桥接不稳定。

**现方案**（[ChecklistItem.vue](file:///d:/Jesse/allinone/allinone-app/src/features/checklist/components/ChecklistItem.vue)）：
- 每个清单项右侧操作区加 ▲▼ 两个按钮
- 第一项 ▲ 禁用，最后一项 ▼ 禁用

### 5.7 GitFast：PTY 终端架构

```
xterm.js（前端）  ←emit/output→  Rust（portable-pty）  ←→  bash 进程
     ↑                                  ↓
     └──invoke/write────────────────────┘
```

- **前端**：xterm.js + FitAddon，自适应尺寸
- **后端**：[gitfast/pty.rs](file:///d:/Jesse/allinone/allinone-app/src-tauri/src/gitfast/pty.rs) 用 `portable-pty` 创建伪终端，每仓库一个 session
- **Shell**：Windows 用 Git Bash（`detect_bash()` 找路径），Mac/Linux 用系统 bash
- **通信**：Rust 读 PTY → Tauri emit `gitfast_pty_output` → xterm 写入；xterm 输入 → invoke `gitfast_pty_write` → Rust 写 PTY

### 5.8 GitFast：配置文件三层覆盖

```
1. 代码内置默认配置（DEFAULT_CONFIG，不可变）
       ↓ 被覆盖
2. 用户加载的 YAML 配置文件（可选）
       ↓ 被覆盖
3. localStorage 运行时状态（UI 临时修改）
```

合并策略：深合并。**配置文件不回写**，用户改配置直接编辑 YAML 文件。

### 5.9 Script Runner：执行模型

与 GitFast 的关键区别：

| 维度 | GitFast | Script Runner |
| --- | --- | --- |
| 执行方式 | PTY（交互式终端） | `std::process::Command`（一次性执行） |
| 仓库数 | 单仓库 | 多仓库批处理 |
| 反馈方式 | 实时终端输出 | 历史记录 + stdout/stderr |
| 并发 | 单仓库 | 串行（P0） |
| 脚本文件 | 不支持 | 支持 `.sh` / `.bat` |

### 5.11 Script Runner：脚本文件识别

[lib.rs](file:///d:/Jesse/allinone/allinone-app/src-tauri/src/lib.rs) 的 `build_shell_command` 按脚本后缀自动选择执行器：

| 脚本结尾 | Windows 执行器 | Mac/Linux 执行器 |
| --- | --- | --- |
| `.sh` / `.bash` | Git Bash（`bash.exe <file>`） | 系统 `bash <file>` |
| `.bat` / `.cmd` | `cmd.exe /C <file>` | 不支持（报错） |
| 其他（命令字符串） | `cmd.exe /C <command>` | `sh -c <command>` |

Windows 上的 bash 路径通过 `detect_bash()` 检测（复用 GitFast 逻辑）。

### 5.12 Script Runner：定时调度与文件日志

- **调度规则**：`interval`（每 N 分钟）/ `daily`（每天 HH:MM）
- **调度器**：浏览器原生 `setInterval`，零新依赖
- **运行时启停**：内存覆盖（`runtimeEnabled` Map），不落盘
- **文件日志**：`<logDir>/<taskId>_<YYYYMMDD_HHMMSS>.log`，含 stdout/stderr/exit_code/duration
- **日志查看**：UI 列出最近 50 条，可查看完整内容、删除

### 5.13 Code Review：参数化脚本执行

Code Review 复用 Script Runner 的 `scripts_run` 命令（已扩展支持 `env` 参数），通过环境变量注入项目信息：

```
用户选源/目标分支
  ↓
store 组装 env（REPO_ID/FULL_NAME/SRC_BRANCH/DEST_BRANCH/PLATFORM_URL/ACCESS_TOKEN/REVIEW_SUBJECT）
  ↓
invoke scripts_run({ script, workdir, env, ... })
  ↓
Rust Command::new(bash).envs(env).spawn()
  ↓
脚本读环境变量 → 调 API → 输出评审 URL
  ↓
结果回传 → UI 显示 + 写文件日志
```

**与 Script Runner 的区别**：

| 维度 | Script Runner | Code Review |
| --- | --- | --- |
| 触发 | 定时 + 手动 | 仅手动 |
| 参数 | 无（配置写死） | 运行时选分支 |
| 配置粒度 | 任务级 | 项目级 + 全局 platform |
| UI | 任务卡片 | 项目卡片 + 分支选择器 |

### 5.14 Code Review：分支搜索选择器

[BranchSelector.vue](file:///d:/Jesse/allinone/allinone-app/src/features/review/components/BranchSelector.vue) 实现可搜索的下拉选择：

### 5.15 笔记：阅读/编辑双模式

笔记工具（v0.7 新增）采用双模式设计，与清单的"清单项交互"模式形成互补。

| 维度 | 清单工具 | 笔记工具 |
| --- | --- | --- |
| 内容结构 | 强结构化（## 待办段 + `- [ ]`） | 弱结构化（自由 Markdown） |
| 主要操作 | 勾选/迁移/置顶 | 编辑/阅读/检索 |
| 编辑方式 | 行级原子操作 | 整文件编辑 |
| 视图侧重 | 列表交互 | 阅读体验 + 编辑体验 |

**模式切换设计**：

- 打开笔记默认进入**阅读模式**（浏览频率 > 编辑频率，避免误改）
- 阅读模式：[NoteReader.vue](file:///d:/Jesse/allinone/allinone-app/src/features/notes/components/NoteReader.vue) 用 `marked` 渲染 HTML，双击正文进入编辑
- 编辑模式：[NoteEditor.vue](file:///d:/Jesse/allinone/allinone-app/src/features/notes/components/NoteEditor.vue) 用 CodeMirror 6
- 顶部「📖 阅读 / ✏️ 编辑」按钮切换；编辑→阅读自动保存（`switchMode` 内调用 `persist`）

**保存策略**：
- 编辑器 `onChange` 仅更新内存（`setCurrentContent`），不立即写盘
- Ctrl+S 手动保存 / 切换模式自动保存
- `dirty` 计算属性 = `currentContent !== savedContent`，顶栏显示"● 未保存"徽标

### 5.16 笔记：CodeMirror 6 集成

[NoteEditor.vue](file:///d:/Jesse/allinone/allinone-app/src/features/notes/components/NoteEditor.vue) 关键实现：

- **挂载**：`onMounted` 创建 `EditorView`，`onBeforeUnmount` 销毁
- **内容同步**：`EditorView.updateListener` 监听 `docChanged` → `store.setCurrentContent`
- **主题动态切换**：用 `Compartment` 持有主题扩展，`watch(theme.mode)` 时 `reconfigure`（无需重建实例）
- **快捷键**：`keymap.of([{ key: 'Mod-s' }, { key: 'Mod-e' }])`
- **文件切换重建**：`watch(currentFilePath)` 触发 `initEditor` 重新加载内容
- **工具栏**：通过 `view.dispatch({ changes })` 操作选区，实现 B/I/H1-H3/引用/列表/链接/代码块插入

**为何用 `shallowRef` 持有 EditorView**：避免 Vue 对 CodeMirror 内部状态做深度响应式代理，保证性能和正确性。

### 5.17 笔记：文件元数据与冲突检测

**元数据列表**：`notes_list_md_files` 命令一次返回所有 .md 文件的 name/mtime/size，减少前端 N 次 IPC。侧边栏按「置顶在前 → 修改时间倒序」排序。

**冲突检测**（[stores/notes.ts](file:///d:/Jesse/allinone/allinone-app/src/features/notes/stores/notes.ts) 的 `persist`）：
1. 打开文件时记录 `lastLoadedMtime`
2. 保存前调用 `notes_file_stat` 获取当前 mtime
3. 若 `currentMtime > lastLoadedMtime` 且本地有改动 → 弹 confirm 提示"文件已被外部程序修改"
4. 用户确认后强制覆盖，更新 `lastLoadedMtime`

### 5.18 笔记：右键菜单与文件操作

[NotesSidebar.vue](file:///d:/Jesse/allinone/allinone-app/src/features/notes/components/NotesSidebar.vue) 右键菜单（复用清单的 ctxMenu 模式，扩展为三项）：

| 菜单项 | 实现 |
| --- | --- |
| 📁 打开所在文件夹 | 复用 `open_in_explorer` 命令 |
| ✏️ 重命名 | `notes_rename_file` 命令，同步迁移置顶状态（旧路径→新路径） |
| 🗑️ 删除 | `notes_delete_file` 命令，二次确认 |

**重命名时置顶迁移**：filePin 以 path 为 key，重命名后旧 key 失效。`renameNote` action 自动执行 `toggleFilePin(oldPath)` + `toggleFilePin(newPath)` 迁移。

### 5.19 笔记：置顶状态独立存储

笔记工具有独立的 filePin（[features/notes/lib/filePin.ts](file:///d:/Jesse/allinone/allinone-app/src/features/notes/lib/filePin.ts)），localStorage key 为 `allinone-notes-pinned-files`，**与清单的置顶相互独立**。

设计理由：遵循 features 隔离原则，两个工具对同一文件的置顶偏好可能不同（如清单里置顶日报、笔记里不置顶），独立存储更符合用户预期。

## 八、常见问题

**Q：点击新建清单无反应？**
A：已修复。原因是 Tauri 2.0 fs 插件 scope 限制。现改为自定义 Rust 命令绕开 scope。

**Q：Rust 编译报 "link.exe not found"？**
A：缺 MSVC 工具链。装 Visual Studio Build Tools 2022，勾选"使用 C++ 的桌面开发"。

**Q：Rust 编译报 "code: 0 操作成功完成" panic？**
A：Rust 1.95.0 工具链 bug。项目已用 `rust-toolchain.toml` 固定 1.94.0。

**Q：tauri build 下载 NSIS 失败（TLS 错误）？**
A：网络问题。方案1：设置代理 `$env:HTTPS_PROXY = "http://127.0.0.1:7890"`。方案2：用 `cargo build --release` 只编译 exe。

**Q：GitFast 终端启动失败？**
A：检查是否安装 Git for Windows。`detect_bash()` 会从 `C:\Program Files\Git\bin\bash.exe` 查找，找不到退回 PATH 中的 bash。

**Q：Script Runner 跑 .sh 脚本失败？**
A：同上，依赖 Git Bash。脚本内的相对路径相对的是**仓库目录**（`current_dir` 已设为仓库路径）。

**Q：置顶状态会同步到 Obsidian 吗？**
A：不会。项级和文件级置顶均仅存应用 localStorage，md 文件保持纯净。

**Q：自定义清单名称输入了非法字符？**
A：自动替换 `\/:*?"<>|` 为 `_`。如输入 `a/b:c` 会生成 `a_b_c.md`。

**Q：GitFast 的定时任务（Timer）去哪了？**
A：已移除。定时执行需求统一由"📜 Script Runner"工具承担，功能更强大（支持任意脚本、完整日志文件、可查看历史）。

**Q：笔记和清单可以共用同一个文件夹吗？**
A：可以。两者都只读写 `.md` 文件，不修改目录结构。但建议分开目录使用，避免清单的日期文件和笔记混在一起。两者的置顶状态相互独立（不同 localStorage key）。

**Q：笔记编辑器为什么选 CodeMirror 而不是 textarea？**
A：CodeMirror 6 提供 Markdown 语法着色、行号、查找替换、撤销栈、多光标等编辑器必备能力，包体积增量约 85KB（gzip），是 textarea 体验的质的飞跃。详见 [3.4 节](#34-关键决策笔记编辑器选-codemirror-6)。

**Q：笔记在外部被修改后会怎样？**
A：保存时应用会检测文件 mtime，若外部已修改且本地也有改动，会弹确认框提示"文件已被外部程序修改，是否覆盖"。

**Q：重命名笔记后置顶状态会丢失吗？**
A：不会。置顶以文件路径为 key，重命名时应用自动把旧路径的置顶状态迁移到新路径。
